## PHASE: Paper Retrieval & Screening

Your task: Retrieve the confirmed target paper, search for relevant related papers,
classify and rank them. The Orchestrator constructs and saves the final candidate
artifact from tool facts. Do not generate or save the final candidate set yourself.

**IMPORTANT**: Search results have already been deduplicated across queries by the Orchestrator. You just need to classify, rank, and select top papers.

### Workflow (follow exactly, 4-6 steps MAX):
1. The orchestrator injects a mandatory `target_paper_fetch` step using
   `arxiv_get_paper` when `target_paper_arxiv_id` is present. Do not replace,
   skip, or filter this exact-ID fetch.
2. Use arxiv_search **2-3 times** with different keyword combinations for
   related papers (NOT 6+!). Use categories ["cs.CV", "cs.AI", "cs.LG"] and
   max_results=15.
3. Keep the exact target paper in `target_paper`, `candidates`, and
   `top_recommendations`, even if keyword search does not return it.
4. After searches, select TOP 10 related papers total (after pre-dedup)
5. Classify each: survey, method, benchmark, application, experimental
6. Rank by: relevance → reproducibility → recency
7. Return only the bounded ranking instructions below. Do not call save_artifact
   for "paper_candidates"; the Orchestrator owns that artifact.

### Available tools:
- arxiv_search (max_results=15, include categories)
- arxiv_get_paper (exact target retrieval, orchestrator-injected)
- save_artifact (artifact_name, data)

### Output format (synthesize result, CONCISE!):
```json
{
  "classifications": [
    {
      "arxiv_id": "xxxx.xxxxxv1",
      "type": "method",
      "relevance_score": 0.9,
      "reproducibility_score": 0.8,
      "recency_score": 0.7,
      "reason": "short reason, at most 300 characters"
    }
  ],
  "ordered_ids": ["target_id", "related_id"],
  "ranking_rationale": "short rationale, at most 1000 characters"
}
```

Only reference IDs returned by the tools. Do not invent titles, URLs, code
availability, licenses, versions, or data availability. Tool facts always win.
