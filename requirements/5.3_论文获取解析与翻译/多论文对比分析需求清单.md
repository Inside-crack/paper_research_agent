# 5.3 论文获取、解析与翻译：多论文对比分析需求清单

**需求类型**：功能增强  
**所属模块**：论文获取、解析与翻译（P10-P14、P30）  
**需求名称**：多论文对比分析 Workflow  
**优先级**：P1  
**状态**：需求骨架已确定，待实现

> 本需求用于支持对多篇论文进行统一获取、解析和横向对比。
> 第一阶段不执行论文代码复现，不依赖论文代码仓库是否可用。

## 一、需求背景

当前系统主要围绕单篇论文处理：

```text
ResearchSpec
    -> 一个目标论文
    -> PaperProcessingWorkflow
    -> 一个 PaperArtifact
```

用户希望对多篇论文进行方法、实验和局限性对比。该能力应复用现有论文
获取、下载、解析、总结和持久化能力，并新增独立的对比分析 Workflow。

## 二、需求目标

1. 支持用户指定两篇或多篇论文进行对比分析。
2. 支持复用系统已经下载、解析或总结过的论文。
3. 支持对缺少代码地址或无法复现的论文进行论文内容层面的比较。
4. 保持论文身份确认、任务确认和会话绑定约束。
5. 输出结构化的论文对比 artifact。
6. 不将论文代码复现作为对比分析的前置条件。

## 三、范围

### 3.1 In Scope

- 新增 `paper_comparison` 任务类型。
- 新增 `ComparisonSpec`。
- 新增 `PaperComparisonWorkflow`。
- 新增 `PaperComparisonArtifact`。
- 支持通过 arXiv ID、URL、候选论文序号指定论文。
- 支持复用本地 PaperArtifact 和已下载 PDF。
- 支持调用 `arxiv_get_paper` 获取在线论文元数据。
- 支持调用 `paper_download` 获取缺失 PDF。
- 复用现有论文解析和总结能力。
- 生成对比矩阵、共同点、差异和总结结论。

### 3.2 Out of Scope

- 执行论文代码。
- 验证论文实验结果。
- 自动判断论文代码是否可以运行。
- 访问和分析论文代码仓库内部实现。
- 对不同数据集上的指标进行未经校准的绝对排名。
- 第一阶段支持任意数量论文和复杂自定义比较规则。

## 四、核心需求清单

### C53-01 新增多论文对比任务类型

系统应支持以下任务类型：

```text
topic_research
paper_analysis
paper_comparison
```

`paper_comparison` 表示用户希望对多篇论文进行统一分析，不应被解释为
`reproduction`。

### C53-02 新增 ComparisonSpec

对比任务至少应保存：

```text
comparison_id
user_query
paper_refs
comparison_dimensions
domain
translation_language
```

其中 `paper_refs` 保存用户确认的论文 ID、URL或候选引用。

第一阶段默认支持 2-5 篇论文。

### C53-03 新增 PaperComparisonWorkflow

系统应新增独立的 `PaperComparisonWorkflow`，不修改现有
`PaperProcessingWorkflow` 的单论文职责。

建议流程：

```text
comparison_initialization
    -> paper_acquisition
    -> paper_parsing
    -> comparison_analysis
    -> comparison_reporting
```

`PaperComparisonWorkflow` 负责协调多篇论文处理和最终对比产物生成。

### C53-04 论文获取来源

对比 Workflow 应通过统一的论文获取入口获取论文，来源包括：

```text
1. 已有完整 PaperArtifact
2. 已有本地 PDF
3. 已有论文元数据
4. arxiv_get_paper
5. paper_download
```

获取优先级：

```text
已有 PaperArtifact
    -> 已有 PDF
    -> 已有元数据
    -> 在线获取元数据
    -> 下载 PDF
```

### C53-05 复用已有论文

系统应支持将已经存在的论文加入对比任务：

- 已有完整 `PaperArtifact` 时直接复用；
- 只有 PDF 时复用 PDF，并补充解析；
- 只有元数据时复用元数据，并按需下载 PDF；
- 已有资源不能仅凭文件名复用，必须校验论文 ID或 URL；
- 论文版本不一致时必须显式记录版本差异；
- 复用结果应记录来源为 `local`。

### C53-06 论文身份和去重

系统应对以下表示进行统一归一化：

```text
2108.01343
2108.01343v3
arXiv:2108.01343v3
https://arxiv.org/abs/2108.01343v3
```

同一论文只能在对比任务中出现一次。论文身份冲突时不得静默合并，
应返回需要用户确认的错误信息。

### C53-07 论文处理依赖

对比 Workflow 的基础依赖包括：

```text
PaperAcquisitionService
PaperProcessingWorkflow 或其底层解析能力
arxiv_get_paper
paper_download
PaperArtifact 持久化
LLM 对比分析能力
```

第一阶段允许通过串行方式处理论文；后续再增加并发和子任务恢复。

### C53-08 用户触发和确认

系统应新增 `compare_papers` 能力，支持类似请求：

```text
比较 I3CL、DBNet 和 TextSnake
对比候选论文 1、2、4
分析这几篇论文的方法差异
```

触发流程必须为：

```text
识别对比意图
    -> 提取论文引用
    -> 补充或确认论文列表
    -> waiting_confirmation
    -> 用户显式确认
    -> 创建 comparison_analysis 任务
    -> 启动 PaperComparisonWorkflow
```

论文数量、论文身份或比较范围不明确时，系统必须先请求用户补充，
不得由 LLM 自动替换论文。

### C53-09 对比维度

第一阶段提供固定默认维度：

```text
研究问题
核心方法
训练策略
数据集与评价指标
实验结果
优点与局限
```

用户可以指定其中部分维度。未指定维度时使用默认维度。

### C53-10 对比结果产物

对比 Workflow 至少生成：

```text
comparison_spec.json
paper_comparison.json
```

可选生成：

```text
paper_comparison.md
```

系统主产物必须是结构化 JSON，Markdown 仅作为展示结果。

建议最终产物包含：

```text
comparison_id
papers
dimensions
comparison_matrix
commonalities
differences
conclusion
missing_information
```

### C53-11 事实与分析分离

代码负责：

- 论文 ID、标题、作者和版本；
- 论文获取来源；
- 论文 artifact 引用；
- 数据集、指标和论文中报告的实验结果；
- 去重和 Schema 校验。

LLM 负责：

- 解释方法差异；
- 归纳共同点；
- 分析适用场景；
- 总结技术演进和局限。

LLM 不得覆盖工具或论文 artifact 已确认的事实字段。

### C53-12 缺失信息处理

论文未提供代码、数据集、指标或实验细节时，应标记为：

```text
unknown
```

不得将“没有检索到证据”直接写成：

```text
false
不存在
不可复现
```

对比报告必须保留 `missing_information`，说明哪些字段缺少证据。

## 五、Workflow 输入和输出骨架

### 5.1 输入

```python
class PaperComparisonWorkflowInput:
    comparison_spec: ComparisonSpec
    confirmed_papers: list[PaperRef]
    existing_artifacts: list[str]
    existing_pdfs: list[str]
```

### 5.2 输出

```python
class PaperComparisonWorkflowOutput:
    comparison_artifact: str
    paper_artifacts: list[str]
    report_artifact: str | None
    missing_information: list[str]
```

## 六、任务和状态流转

```text
waiting_user_input
    -> waiting_paper_selection
    -> waiting_confirmation
    -> running
    -> completed
```

任务阶段建议为：

```text
comparison_initialization
comparison_retrieval
comparison_analysis
comparison_reporting
```

第一阶段可以先在现有任务生命周期中以一个独立 Workflow 执行，
不要求立即新增大量顶层阶段。

## 七、验收标准

- [ ] 用户可以指定至少两篇论文启动对比任务。
- [ ] 用户未确认前不会启动对比 Workflow。
- [ ] 已下载论文可以被对比任务复用。
- [ ] 已解析 PaperArtifact 可以跳过重复解析。
- [ ] 缺少本地资源时可以通过 arXiv 获取。
- [ ] 同一论文的不同 ID/URL表示不会重复出现。
- [ ] 对比任务产出可解析的 `paper_comparison.json`。
- [ ] 对比矩阵包含每篇已确认论文。
- [ ] 缺失信息被标记为 `unknown` 或写入 `missing_information`。
- [ ] LLM无法覆盖论文身份和工具事实。
- [ ] 对比任务不依赖论文代码存在或代码可运行。
- [ ] 任务、会话、artifact 和事件均保持关联。

## 八、建议实现顺序

1. 新增 `ComparisonSpec` 和 `PaperComparisonArtifact`。
2. 新增论文本地资源索引或复用现有 Manifest 查询能力。
3. 抽象 `PaperAcquisitionService`，统一本地和在线获取。
4. 新增 `PaperComparisonWorkflow` 骨架。
5. 新增 `compare_papers` 能力和确认路由。
6. 复用已有论文解析和总结产物。
7. 实现基础对比矩阵和 JSON 持久化。
8. 增加离线单元测试、Workflow 测试和 CLI 验收。
