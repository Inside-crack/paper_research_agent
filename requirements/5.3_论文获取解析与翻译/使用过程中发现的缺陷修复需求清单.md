# 5.3 论文获取、解析与翻译：使用过程中发现的缺陷修复需求清单

**需求类型**：使用过程中发现的缺陷修复需求  
**所属模块**：论文获取、解析与翻译（P10-P14、P30）  
**发现日期**：2026-08-26  
**发现方式**：CLI 实际使用与论文处理任务评估  
**总体优先级**：P0/P1  
**状态**：已完成问题归纳，部分缺陷已有修复，质量输出缺陷待继续修复

> 本文档不是原始功能需求，而是系统在真实 CLI 使用和任务评估过程中暴露出的缺陷修复清单。
> 后续实现、测试和验收应以本文档的问题描述与验收标准为依据。

## 一、问题背景

在处理已确认论文 `arXiv:2108.01343v3`（I3CL）时，任务曾在
`paper_retrieval` 阶段失败。初始失败表现为：已确认的目标论文没有进入
候选集和推荐列表。修复目标论文直取逻辑后，目标论文能够被
`arxiv_get_paper` 获取并进入推荐列表，但后续评估仍发现检索输出存在事实
不一致、JSON 截断和可复现性信息缺失等问题。

## 二、缺陷清单

### D53-01 目标论文未进入论文获取节点

**优先级**：P0  
**原始表现**：

- 已确认目标论文 ID 已进入任务上下文；
- `paper_retrieval` 只执行了 `arxiv_search`；
- 未对目标论文 ID 调用 `arxiv_get_paper`；
- 目标论文属于 `cs.CV`，被原有 `cs.AI/cs.CL/cs.LG` 分类限制遗漏；
- 评估器因目标论文不在候选集和推荐列表而触发阻断。

**修复要求**：

- 将 `target_paper_arxiv_id` 作为 `paper_retrieval` 的结构化输入；
- 阶段启动时强制调用 `arxiv_get_paper`；
- 精确获取目标论文与相关论文搜索分为两条独立路径；
- 目标论文必须进入 `target_paper`、`candidates` 和
  `top_recommendations`；
- 相关论文搜索至少支持 `cs.CV`。

**当前状态**：部分完成。代码已增加目标论文直取和结果注入，真实 CLI 已验证
`target_paper_verified=true`，但仍需补充完整端到端回归测试。

### D53-02 目标论文事实字段被 LLM 错误覆盖

**优先级**：P0  
**原始表现**：

- arXiv 的 `comment` 和摘要中包含 GitHub 代码地址；
- 最终输出却为：

```json
{
  "code_available_hint": false,
  "code_url_hint": null
}
```

**修复要求**：

- 工具返回的论文元数据视为事实来源；
- 从 `comment`、摘要和链接中确定性提取 GitHub URL；
- 发现有效 GitHub URL 时，代码必须写入：
  `code_available=true` 和 `code_url`；
- LLM 不得覆盖工具事实字段；
- 工具事实与推断字段分离保存。

**验收标准**：

- I3CL 输出 `code_available=true`；
- `code_url` 为
  `https://github.com/ViTAE-Transformer/ViTAE-Transformer-Scene-Text-Detection`；
- 评估器不再报告目标论文代码可用性矛盾。

### D53-03 LLM 直接生成最终候选集导致 JSON 截断

**优先级**：P0  
**原始表现**：

- `search_queries_used` 或 `ranking_rationale` 在生成过程中被截断；
- 输出缺少闭合括号或闭合对象；
- 下游无法可靠解析和验证检索产物；
- revise 仍可能重复生成截断内容。

**修复要求**：

- 不允许 LLM 直接生成最终候选集 artifact；
- 由代码合并工具结果、去重、补齐字段和序列化；
- 使用 Pydantic/JSON Schema 校验最终输出；
- LLM 只返回有限长度的排序 ID、分类和简短理由；
- 对理由文本设置长度上限；
- JSON 校验失败时走确定性 fallback，不得保存原始不完整文本。

**验收标准**：

- `paper_candidates.json` 始终是可解析的完整 JSON；
- `search_queries_used`、`ranking_rationale` 均完整存在；
- 连续运行和 revise 不会产生半截 artifact。

### D53-04 候选论文排序缺少可复现性依据

**优先级**：P1  
**原始表现**：

- 候选论文只有相关性分数和文字理由；
- 没有代码 URL、许可证、版本、数据集等可复现性信息；
- 排序理由声称考虑了可复现性，但候选字段未提供对应证据。

**修复要求**：

- 为候选论文增加结构化可复现性字段：
  `code_available`、`code_url`、`license`、`version`、`data_available`；
- 区分“工具确认”和“LLM 推断”；
- 排序依据显式包含：
  相关性、可复现性、时效性；
- 目标论文也必须拥有完整的排序理由和类型字段；
- 没有证据时标记为 `unknown`，不能填写 `false` 伪装成已确认。

**验收标准**：

- 每个推荐候选有 `relevance_score` 和 `reason`；
- 每个候选的代码可用性均有证据来源或 `unknown` 标记；
- `ranking_rationale` 与实际字段一致。

### D53-05 目标论文与相关论文合并去重不够稳定

**优先级**：P1  
**原始表现**：

- 目标论文可能同时出现在精确获取结果和关键词搜索结果中；
- 候选列表存在重复或字段不一致；
- arXiv 版本号、URL 和裸 ID 的格式可能导致去重失败。

**修复要求**：

- 统一使用规范化 arXiv ID 去重；
- `2108.01343`、`2108.01343v3` 和 arXiv URL 应归一到同一论文；
- 目标论文以精确获取结果为准；
- 合并后目标论文只能出现一次；
- 目标论文必须排在候选列表首位。

**验收标准**：

- 不同 ID/URL 表示不会生成重复候选；
- 目标论文在 `candidates` 中仅出现一次；
- `top_recommendations` 中使用统一 ID 格式。

### D53-06 任务初始化阶段产生与输入不符的歧义说明

**优先级**：P1  
**原始表现**：

- 输入 `ResearchSpec` 已明确为 `paper_analysis`；
- 输出却声称系统将 `topic_research` 重新解释为 `paper_analysis`；
- 输入已包含 domain 和 time_range；
- 输出却声称这些字段缺失。

**修复要求**：

- 歧义字段只能引用真实存在于输入中的冲突；
- 已提供的字段不得被描述为缺失；
- 初始化阶段保留原始 `ResearchSpec`，不得由 LLM 改写事实；
- 增加初始化输出与输入的确定性一致性检查。

**验收标准**：

- 不再生成 `INIT-001` 和 `INIT-002` 类问题；
- `task_type`、`domain`、`time_range` 与原始输入一致；
- 无真实歧义时 `ambiguities` 为空。

### D53-07 论文处理确认路由不稳定

**优先级**：P1  
**原始表现**：

- “处理当前选中的论文”等确认意图曾被再次路由到 `paper_search`；
- 需要额外输入“处理这篇论文”才能进入确认门禁；
- 错误路由可能造成重复搜索或状态转换失败。

**修复要求**：

- 增加显式 `/process` 入口；
- 选中论文后，处理意图必须路由到 `process_selected_paper`；
- 启动完整处理前仍必须经过用户显式确认；
- 确认文本不得重新创建 `paper_search` 任务；
- 增加 `waiting_confirmation -> running` 回归测试。

**当前状态**：部分完成。CLI 已增加 `/process`，仍需补充自然语言路由和端到端状态测试。

## 三、统一目标输出契约

`paper_retrieval` 最终产物至少应满足以下结构：

```json
{
  "target_paper": {
    "arxiv_id": "2108.01343v3",
    "title": "I3CL:Intra- and Inter-Instance Collaborative Learning for Arbitrary-shaped Scene Text Detection",
    "type": "method",
    "relevance_score": 1.0,
    "code_available": true,
    "code_url": "https://github.com/ViTAE-Transformer/ViTAE-Transformer-Scene-Text-Detection"
  },
  "target_paper_verified": true,
  "candidates": [],
  "top_recommendations": ["2108.01343v3"],
  "search_queries_used": [],
  "ranking_rationale": ""
}
```

确定性约束：

```text
target_paper_verified == true
target_paper.arxiv_id == confirmed_target_arxiv_id
confirmed_target_arxiv_id ∈ candidates
confirmed_target_arxiv_id ∈ top_recommendations
paper_candidates.json 可被标准 JSON 解析
```

## 四、建议修复顺序

1. **P0**：目标论文直取、目标论文强制保留、工具事实优先；
2. **P0**：代码生成最终候选集并增加 Schema 校验，消除 JSON 截断；
3. **P1**：补充可复现性字段和确定性排序；
4. **P1**：修复初始化歧义信息与 CLI 处理确认路由；
5. **P0/P1**：补充单测、集成测试和一次真实 CLI 端到端验证。
