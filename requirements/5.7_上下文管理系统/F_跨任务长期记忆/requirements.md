# F：跨任务长期记忆系统需求清单

**模块编号**：F  
**模块名称**：跨任务长期记忆系统  
**所属模块**：5.7 上下文管理系统  
**创建日期**：2026-08-27  
**状态**：需求已拆分，尚未实现  
**设计参考**：`附加学习知识/tencentdb-agent-memory-summary-and-fulltext.md`

---

## 一、目标

在现有“会话消息、任务状态、阶段摘要、Artifact”体系之外，增加一个独立的长期记忆层，使 Agent 能够：

1. 从已确认、可复用的信息中提取记忆；
2. 在不同任务之间按用户和研究主题召回相关记忆；
3. 对新旧记忆进行去重、更新、合并和冲突处理；
4. 保留每条记忆的来源、版本和审计信息；
5. 在记忆系统异常时不阻塞论文研究主流程。

## 二、边界定义

### 2.1 信息分层

| 层级 | 内容 | 责任模块 |
|------|------|----------|
| L0 | 原始会话消息、工具调用、任务事件 | `ConversationStore`、`EventStore` |
| L1 | 可独立理解的原子长期记忆 | 新增 `MemoryStore` |
| L2 | 研究主题、论文集合、实验方向的归纳知识 | 后续阶段 |
| L3 | 稳定的用户研究画像和行为偏好 | 后续阶段 |
| 工作记忆 | 当前任务状态、阶段摘要、上下文压缩结果 | `TaskState`、Context Management |

### 2.2 首期明确不做

- 不把所有任务 Artifact 自动转为用户长期记忆；
- 不用长期记忆替代 `TaskState`、checkpoint 或 Manifest；
- 不允许历史记忆直接证明当前任务已经完成；
- 不在首期引入 LLM 自主维护 Markdown 场景目录；
- 不在首期引入向量数据库、分布式队列或代理接入层；
- 不在首期自动生成不可审计的 Persona 结论。

## 三、需求清单

### F01：长期记忆数据模型

**优先级**：P0  
**目标**：建立可校验、可追溯的 `MemoryItem` 和 `MemoryCandidate` 模型。

- [x] 定义 `MemoryType`：`persona`、`instruction`、`episodic`、`research_fact`、`failure_lesson`；
- [x] 定义 `MemoryScope`：`user`、`research_topic`、`agent`；
- [x] 记录 `memory_id`、内容、类型、优先级和置信度；
- [x] 记录 `owner_user_id`、`source_session_id`、`source_task_id`；
- [x] 记录 `source_message_id`、`source_artifact_ids`；
- [x] 记录创建、更新时间、过期时间和版本号；
- [x] 定义状态：`active`、`superseded`、`expired`、`deleted`；
- [x] 使用 Pydantic 校验，禁止未知字段；
- [ ] 支持旧数据向后兼容。

**验收标准**：

- 无来源的长期记忆不能进入 `active` 状态；
- 记忆模型能通过 JSON 序列化和反序列化；
- 记忆来源至少关联一个会话、任务或用户确认事件。

### F02：L0 原始记录与记忆候选分离

**优先级**：P0  
**目标**：确保原始事实和提炼后的长期记忆可分别追溯。

- [x] 保持 `ConversationStore` 原始消息不可被记忆提炼覆盖；
- [x] 增加 `MemoryCandidate`，作为待审核/待整合的中间状态；
- [x] 候选记忆必须包含原始消息或 Artifact 引用；
- [x] 区分用户明确陈述、用户确认、Agent 推断和工具事实；
- [x] 默认只从用户明确表达、用户确认、确定性工具事实中生成候选；
- [x] 未确认的 LLM 推断默认不得写入用户长期记忆。

**验收标准**：

- 删除或修改长期记忆不会删除原始会话；
- 任意长期记忆可以回查到原始来源；
- 任务中间结果不会自动升级为用户偏好。

### F03：记忆提取策略

**优先级**：P0  
**目标**：从运行事件中提取少量高价值记忆。

- [x] 支持从用户消息中提取长期偏好和行为规则；
- [x] 支持从确认动作中提取已确认事实；
- [x] 支持从任务完成结果中提取经过校验的研究结论；
- [x] 支持从失败诊断中提取可复用的失败经验；
- [x] 过滤一次性指令、临时搜索结果和纯情绪表达；
- [x] 要求记忆脱离原始上下文后仍然独立可读；
- [x] 使用“宁缺毋滥”策略，首期限制每个事件产生的候选数量；
- [x] 记录提取器版本和提取原因。

**验收标准**：

- 同一条消息不会因重复处理产生无限候选；
- 候选记忆包含明确主体、事实和必要时间信息；
- 提取失败时主任务继续运行并记录 warning。

### F04：记忆持久化

**优先级**：P0  
**目标**：提供独立于任务 Artifact 的长期记忆存储。

- [x] 新增 `MemoryStore`；
- [x] 首期使用 SQLite 或原子 JSON 实现，不依赖外部服务；
- [x] 支持创建、读取、更新、删除和列举记忆；
- [x] 支持按 `user_id`、scope、type、status 过滤；
- [x] 写入使用原子操作；
- [x] 记录幂等键，避免任务恢复或重试导致重复写入；
- [x] 记忆索引损坏时支持从原始表重建；
- [x] 记忆存储失败时不能使论文主流程失败。

**验收标准**：

- 进程重启后长期记忆仍可读取；
- 同一幂等键重复写入不会创建重复记录；
- 写入中断不会留下无法解析的半成品；
- 不同用户的数据无法互相读取。

### F05：去重、更新与冲突合并

**优先级**：P0  
**目标**：避免长期记忆无限增长和错误累积。

- [x] 先通过结构化字段、关键词或相似度召回候选记忆；
- [x] 支持 `store`、`skip`、`update`、`merge` 四种处理结果；
- [x] 新记忆更准确时更新旧记忆；
- [x] 新旧记忆互补时合并内容；
- [x] 新旧记忆冲突时保留冲突记录，不静默覆盖；
- [x] 更新和合并保留全部相关时间戳；
- [x] 旧记忆变为 `superseded`，不得物理删除来源；
- [x] 状态转换由代码校验和写入，后续 LLM 仅可作为语义判断器；
- [x] 限制单次整合涉及的候选数量。

**验收标准**：

- 重复表达不会持续新增记忆；
- 用户后续纠正能够覆盖或标记旧记忆；
- 任何更新都能查看前后版本和处理原因；
- 去重服务异常时可降级为新增候选，不阻塞主流程。

### F06：跨任务记忆召回

**优先级**：P0  
**目标**：将与当前请求相关的长期记忆安全地提供给 Agent。

- [x] 扩展 `IntentContextProjector`，增加受限的 `relevant_memories`；
- [x] 按 `user_id` 和 scope 做强隔离；
- [x] 首期支持关键词和结构化过滤；
- [ ] 预留 embedding + FTS5 + RRF 的混合检索接口；
- [x] 默认只召回 Top-K 记忆；
- [x] 设置字符/token预算；
- [x] 记忆按照相关性、优先级、时效性排序；
- [x] 召回结果携带来源引用和置信度；
- [x] 召回结果明确标记为历史参考，不代表当前任务状态。
- [x] 召回接口必须要求 `owner_user_id`，禁止无 Owner 全库搜索；
- [x] 召回默认排除 `deleted`、`expired`、`superseded` 记忆；
- [x] 召回结果必须保留 `memory_id`、来源引用和相关性分数；
- [x] 召回后端故障时回退到关键词检索或返回空结果；
- [x] 召回日志不得记录完整私有记忆内容。

**验收标准**：

- 任务 B 可以召回任务 A 产生的有效长期记忆；
- 无关记忆不会因为仅有弱关键词匹配而大量注入；
- 召回结果超过预算时可预测地截断；
- 召回超时或失败时返回空记忆并继续主流程。
- 召回不会读取或修改 `TaskState`；
- 任务恢复时通过 `memory_id` 重新召回，不复制长期记忆全文；
- 同一 Owner 的相同查询在预算内得到稳定、可解释的排序结果。

### F07：长期记忆注入与上下文预算

**优先级**：P1  
**目标**：将长期记忆接入现有上下文管理，而不破坏阶段隔离。

- [x] 稳定记忆和动态召回记忆分开注入；
- [x] 动态记忆不进入长期稳定 System Prompt 区域；
- [x] 保留 System Prompt、ResearchSpec、当前阶段 Prompt 等锚点；
- [x] 长期记忆不能覆盖当前 `TaskState`；
- [x] 记忆注入有独立的字符/token上限；
- [x] 超限时优先减少低优先级历史记忆；
- [ ] 截断时提示可通过记忆搜索工具继续查询；
- [x] 阶段切换后不得携带上一任务的原始消息历史。
- [x] `ContextProjector` 不直接访问文件系统，只接收已召回记忆；
- [x] 动态召回内容放在本轮上下文，不污染稳定 System Prompt；
- [x] 每个 ResearchAgent 阶段基于当前阶段和历史摘要重新召回动态记忆；
- [x] 历史记忆明确标注为参考，不能覆盖工具事实和当前任务状态。

**验收标准**：

- 记忆注入不会破坏现有 A01-C03 上下文管理测试；
- 历史任务的“已完成”信息不会改变当前任务状态；
- 记忆注入失败不影响正常计划生成和工具执行。

### F08：记忆写入生命周期与异步可靠性

**优先级**：P1  
**目标**：保证记忆提炼的最终一致性和可恢复性。

- [x] 任务完成和明确用户确认节点触发记忆候选写入；
- [x] 支持后台异步整合；
- [x] 记录处理状态和 checkpoint；
- [x] 支持有限次数重试和指数退避；
- [x] 同一用户/Agent 的记忆整合过程串行化；
- [x] 失败任务进入可查询的 dead-letter 或 failed 状态；
- [x] 支持进程重启后继续处理未完成候选；
- [x] 记忆写入失败不阻塞对话和论文处理主链路；

**验收标准**：

- 进程异常重启后不会丢失已落盘候选；
- 重试不会造成重复写入；
- 连续失败可定位原因并支持人工重放；
- 主任务响应不依赖异步记忆整合完成。

### F09：记忆权限、隐私和生命周期

**优先级**：P1  
**目标**：让长期记忆具备可治理性。

- [ ] 默认按用户隔离长期记忆；
- [ ] `private` 记忆只有 Owner 可访问；
- [ ] 区分 user、agent、research_topic 等 scope；
- [ ] 支持查看记忆及其来源；
- [ ] 支持用户主动修改和删除；
- [ ] 支持过期时间和自动失效；
- [ ] 删除后召回接口不得返回已删除记忆；
- [ ] 记录访问、修改和删除审计事件；
- [ ] 不把私有用户偏好自动共享给团队或其他 Agent。

**验收标准**：

- 权限检查在召回前完成；
- 用户删除记忆后无法通过旧索引召回；
- 管理操作不能绕过 private 记忆的 Owner 限制。

### F10：记忆查询和运维能力

**优先级**：P1  
**目标**：提供可观测、可调试、可维护的记忆管理能力。

- [ ] 增加记忆列表、查询、详情和来源追踪接口；
- [ ] 支持按任务、会话、类型、状态查询；
- [ ] 支持查看记忆版本链和冲突记录；
- [ ] 记录写入、整合、召回、降级和删除事件；
- [ ] 增加 CLI 调试命令；
- [ ] 输出召回数量、耗时、截断数量和失败原因；
- [ ] 提供记忆统计：总量、活跃量、过期量、重复率；
- [ ] 记忆后端故障应有明确 warning，而非静默伪成功。

**验收标准**：

- 可以从一条记忆定位到来源任务和原始消息；
- 可以解释某次召回为什么命中；
- 可以确认某次记忆未注入的原因；
- 运维查询不修改记忆内容。

## 五、全局非功能要求

- **可追溯**：每条长期记忆必须能定位原始来源；
- **可恢复**：进程重启、任务重试和索引损坏不能造成不可解释的数据丢失；
- **可降级**：记忆系统超时或故障时，主任务照常运行；
- **可校验**：模型、状态转换和持久化内容由代码校验；
- **低侵入**：不改变现有 Orchestrator、Workflow 和 Artifact 的职责边界；
- **隐私优先**：默认用户隔离，私有记忆不可被管理员越权读取；
- **成本可控**：限制候选数量、召回数量、注入预算和主动搜索次数；
- **确定性优先**：LLM 负责语义提炼和判断，代码负责权限、状态转换、事实合并和持久化。
