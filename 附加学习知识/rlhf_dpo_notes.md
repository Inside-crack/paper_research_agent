# 大模型对齐：RLHF 与 DPO 原理笔记

> 整理自学习讨论，覆盖 RLHF 三步流程、KL 散度惩罚原理、DPO 数学推导。

---

## 一、问题背景：为什么需要对齐？

GPT-3 的预训练目标是"预测下一个词"，训练数据是互联网全量文本——包括新闻、论坛、小说、代码……

**互联网文本 ≠ 好的对话**：
- 大量文本不是问答格式，而是叙述性的
- 互联网上有大量有害、偏激、错误内容
- 模型学到的是"模仿文本分布"，而不是"帮助用户解决问题"

结果：GPT-3 会续写，但不会"回答"；会生成流畅文本，但可能有害。

**核心矛盾**：模型能力强，但不好用。

---

## 二、RLHF 三步流程

---

### 第一步：SFT（有监督微调，Supervised Fine-Tuning）

**做法**：
- 人工标注员写大量高质量的"指令 → 回答"对
- 用这批数据对预训练模型做微调

```
指令："帮我写一封请假邮件"
回答：[标注员写的高质量示范回答]
```

**目的**：让模型学会对话格式，初步具备"听指令"能力。

**局限**：
- 人工标注成本极高，数量有限
- 光靠模仿示范，模型还不知道什么是"更好的回答"

---

### 第二步：训练奖励模型（Reward Model，RM）

**核心思想**：人类更擅长"比较好坏"而不是"从零写出最好的"。

**做法**：
```
① 对同一个问题，让 SFT 模型生成多个不同回答（比如4个）
② 人类标注员对这4个回答按质量排序
③ 用排序数据训练奖励模型 RM
   RM 的任务：给任意一个回答打一个分数
```

**奖励模型的训练目标**：
```
对于人类认为 A 比 B 好的情况：
Loss = -log(sigmoid(RM(A) - RM(B)))
→ 让 RM(A) > RM(B)，即 RM 打分和人类偏好一致
```

**为什么这样有效**：
- 排序比生成容易，同样的人工成本产生更多训练信号
- RM 训好之后，相当于"克隆了人类评委"，可以自动给无限多的回答打分

---

### 第三步：PPO 强化学习优化

有了会打分的 RM，用它来持续优化语言模型：

```
[语言模型] 生成回答
     ↓
[奖励模型] 给回答打分（reward）
     ↓
[PPO 算法] 根据 reward，更新语言模型参数
           → 让模型倾向于生成高分回答
```

---

## 三、KL 散度惩罚：防止 Reward Hacking

---

### 为什么需要约束？

PPO 的目标是让模型输出被 RM 打高分。但有个危险——**Reward Hacking（作弊）**：
- RM 偏好长回答 → 模型学会无意义堆砌文字
- RM 偏好礼貌语气 → 每句话都加"非常感谢您的提问"
- 极端情况：模型输出乱码，但恰好能骗过 RM 得高分

---

### 什么是 KL 散度？

KL 散度衡量两个概率分布的差异：

```
KL(P || Q) = Σ P(x) × log(P(x) / Q(x))
```

- `KL = 0`：两个分布完全相同
- `KL > 0`：分布有差异，越大差异越大

在 RLHF 里：
- `P` = 当前训练中的模型输出分布
- `Q` = 原始 SFT 模型输出分布
- `KL(P || Q)` = 当前模型偏离 SFT 模型的程度

---

### 完整优化目标

```
Objective = E[RM(response)] - β × KL(π_RL || π_SFT)
```

| 项 | 含义 |
|---|---|
| `E[RM(response)]` | 奖励模型打分，越高越好 |
| `KL(π_RL \|\| π_SFT)` | 当前模型与 SFT 模型的分布差距 |
| `β` | 惩罚系数，控制约束强度（通常 0.01~0.1） |

**两项的博弈**：RM 分高 → 好；但偏离 SFT 太多 → KL 变大 → 惩罚增加。

---

### Token 级别的实现

```python
for t in range(sequence_length):
    p_rl  = rl_model.logprobs(token[t])    # 当前模型对该 token 的概率
    p_sft = sft_model.logprobs(token[t])   # SFT 模型对该 token 的概率
    kl_t  = p_rl * log(p_rl / p_sft)      # 单个 token 的 KL 贡献

# 实际奖励 = RM 得分（序列末尾给一次）- β × 每个token的KL惩罚
r(t) = RM_score - β × KL(t)
```

---

### β 系数的影响

```
β 小（如 0.01）：KL 惩罚弱 → 模型自由探索 → 容易 Reward Hacking
β 大（如 0.5） ：KL 惩罚强 → 模型被锁死 → 几乎不更新，RLHF 失效
```

实践中通常用**自适应 β**：当 KL 超过阈值时自动增大 β，让模型"刹车"。

---

### 直觉类比

> KL 约束就像培养新员工：他可以在工作中成长（PPO 优化），但不能为了得奖励就完全变成另一个人。保留原来的基本素质，别走偏了。

## 四、DPO：用数学消掉 RM 和 PPO

---

### 核心思路

DPO 的聪明之处：把"RM 打分 + KL 惩罚"这个两阶段优化问题，**在数学上推导成等价的封闭形式**，直接用偏好数据训练模型。

---

### 推导过程（5步）

#### Step 1：RLHF 最优解的解析形式

对 RLHF 优化目标用变分法，可以推出最优策略：

```
π*(y|x) = π_SFT(y|x) × exp(RM(x,y) / β) / Z(x)
```

其中 `Z(x) = Σ_y π_SFT(y|x) × exp(RM(x,y) / β)` 是归一化常数。

#### Step 2：反解出 RM 的表达式

把上式反过来，用模型概率比表示 RM：

```
RM(x,y) = β × log(π*(y|x) / π_SFT(y|x)) + β × log Z(x)
```

**关键发现**：RM 分数可以用"当前模型相对于 SFT 模型的概率比"来表示！

#### Step 3：代入偏好概率公式（Bradley-Terry 模型）

人类偏好 y_w 优于 y_l 的概率：

```
P(y_w ≻ y_l | x) = sigmoid(RM(x, y_w) - RM(x, y_l))
```

计算 RM 差值：

```
RM(x, y_w) - RM(x, y_l)
= β×log(π*(y_w|x)/π_SFT(y_w|x)) + β×logZ(x)
- β×log(π*(y_l|x)/π_SFT(y_l|x)) - β×logZ(x)

= β×log(π*(y_w|x)/π_SFT(y_w|x)) - β×log(π*(y_l|x)/π_SFT(y_l|x))
```

**Z(x) 神奇消掉了！** 这是整个推导最优雅的地方。

#### Step 4：得到 DPO 损失函数

```
L_DPO = -E[(y_w, y_l)] × log σ(
    β × log(π_θ(y_w|x) / π_SFT(y_w|x))
  - β × log(π_θ(y_l|x) / π_SFT(y_l|x))
)
```

#### Step 5：理解损失函数在做什么

```
好回答(y_w)：让模型生成它的概率，相对于 SFT，尽量提升  ↑
差回答(y_l)：让模型生成它的概率，相对于 SFT，尽量降低  ↓
两者之差越大，sigmoid 值越高，Loss 越小
```

KL 约束**被自动内嵌**进了损失函数，不需要显式计算。

---

### RLHF vs DPO 对比

| | RLHF | DPO |
|---|---|---|
| 需要单独训 RM | ✅ 是 | ❌ 否 |
| 需要强化学习（PPO） | ✅ 是 | ❌ 否 |
| 需要显式计算 KL | ✅ 是 | ❌ 否（内嵌在损失里）|
| 训练稳定性 | 低（PPO 难调） | 高（普通分类损失）|
| 同时需要的模型数 | 4个（当前/SFT/RM/价值） | 2个（当前/SFT）|
| 效果 | 强 | 接近，部分任务略弱 |

---

### RLHF 之后的改进方向

| 方案 | 做法 | 优点 |
|---|---|---|
| **DPO** | 跳过 RM，直接用偏好数据优化 | 简单稳定，LLaMA 3 等使用 |
| **RLAIF** | 用 AI 代替人类打分 | 降低人工成本，可大规模扩展 |
| **Constitutional AI** | 给模型一套"宪法原则"，让它自我批判 | Anthropic/Claude 使用 |

## 五、总结

```
预训练（自监督）→ 模型学会语言
  ↓
SFT（监督微调）→ 模型初步听指令
  ↓
RLHF（RM + PPO + KL约束）→ 模型输出符合人类偏好
  ↓（简化路线）
DPO（数学等价变换）→ 一个损失函数搞定，KL 自动内嵌
```

> **核心洞见：RLHF 把"什么是好回答"这件主观的事，通过奖励模型量化，再用强化学习让模型持续优化。DPO 进一步发现，这个过程在数学上等价于一个简单的对比学习问题，不需要 RM 和 PPO，大幅降低了对齐的工程复杂度。**
