# Transformer 模型训练与推理原理笔记

> 整理自学习讨论，覆盖 Transformer 核心机制、训练原理、反向传播数学推导。

## 一、模型结构概览

```
输入 Token
  ↓
[Embedding + Positional Encoding]
  ↓
[Encoder Stack]  ← 理解输入（BERT 类模型使用）
  ↓
[Decoder Stack]  ← 生成输出（GPT 类模型使用）
  ↓
[输出 Logits → Softmax → 预测 Token]
```

> 现代主流 LLM（GPT / Claude / DeepSeek）普遍采用 **Decoder-only** 架构。

## 二、核心机制：Self-Attention（自注意力）

### 计算过程

```
输入矩阵 X
  ↓ 三个线性变换（Wq / Wk / Wv 均为可训练参数）
Q = X · Wq
K = X · Wk
V = X · Wv
  ↓
Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V
```

| 矩阵 | 角色 | 学习目标 |
|---|---|---|
| **Q（Query）** | 当前 token 在"问"：我该关注谁？ | 学会"什么样的 token 应该去问什么问题" |
| **K（Key）** | 每个 token 在"说"：我有什么信息？ | 学会"什么样的 token 携带什么类型的信息" |
| **V（Value）** | 实际传递的信息内容 | 学会"被选中后应该贡献什么信息" |

**本质**：每个 token 根据与其他 token 的相关性，加权聚合全局信息。

## 三、多头注意力（Multi-Head Attention）

### 设计动机

类比 CNN 的多通道机制——希望模型同时抓住多个不同方向的特征。

### 做法

```
将输入降维，分成 h 个头，每个头独立做 Attention：
head_i = Attention(X·Wqᵢ, X·Wkᵢ, X·Wvᵢ)

最终合并：
MultiHead = Concat(head₁, ..., headₕ) · Wo
```

### 关键特点

- **零代价多视角**：每头 d_k = d_model / h，总计算量不变，但获得 h 个视角
- **自发分工**：不同头自发学到不同模式（句法、指代、位置、语义相似性等）
- **Wo 可训练**：最后的合并矩阵也是可学习的，负责智能融合各头信息

## 四、训练过程

### 4.1 自监督学习（Self-Supervised Learning）

**核心思想：数据自己给自己出题**

| 类型 | 标签来源 | 代表模型 |
|---|---|---|
| 监督学习 | 人工标注 | 图像分类、NER |
| 自监督学习 | 从数据本身自动生成 | GPT、BERT |

**GPT（只填末尾）**：
```
输入："今天 天气 很"  →  预测："好"
```
单向，适合生成任务。

**BERT（任意位置完形填空）**：
```
输入："今天 [MASK] 很 好"  →  预测："天气"
```
双向，适合理解任务。

### 4.2 完整训练三阶段

```
阶段一：预训练（自监督）
  海量文本 → Next Token Prediction
  → 模型学会语言能力、世界知识

阶段二：SFT 有监督微调（监督学习）
  人工高质量指令-回答对
  → 模型学会"听指令、好好回答"

阶段三：RLHF 强化学习
  人类对模型输出打分 → 训练奖励模型 → PPO 优化
  → 输出更符合人类偏好
```

### 4.3 Causal Mask（因果掩码）

训练时用 Causal Mask 保证每个位置只能看到左边的 token，同时一次前向传播预测所有位置，大幅提升效率：

```
Attention Mask（上三角 = −∞）：
        今天  天气   很   好
今天  [  0    -∞   -∞   -∞ ]
天气  [  0     0   -∞   -∞ ]
很    [  0     0    0   -∞ ]
好    [  0     0    0    0  ]
```

## 五、反向传播与梯度更新

### 5.1 核心工具：链式法则

```
∂Loss/∂W = ∂Loss/∂Z × ∂Z/∂W
```

把复杂梯度拆成多段乘积，从 Loss 出发逐层往前传递。

### 5.2 损失函数：Cross-Entropy

```
Loss = -log P(正确词)
```

梯度（以 5 个词词表为例，正确答案是第3个）：

```
softmax(Logits) = [0.10, 0.05, 0.50, 0.08, 0.04]
one_hot(y)      = [0,    0,    1,    0,    0   ]
∂Loss/∂Logits   = [0.10, 0.05, -0.50, 0.08, 0.04]
```

- 正确词：梯度为负 → 把 Logit 调大（概率升高）
- 错误词：梯度为正 → 把 Logit 调小（概率降低）

**目标**：让正确答案概率趋近 1，其余趋近 0。

### 5.3 Wq 梯度的完整推导链

```
Loss
  ↓ CrossEntropy 求导
dLogits = softmax(Logits) - one_hot(y)      【起点，直接算】
  ↓ × Woutᵀ （同时更新 Wout）
dOut
  ↓ Out = A·V，矩阵乘法求导 × Vᵀ
dA
  ↓ softmax 反向传播
dScore
  ↓ Score = Q·Kᵀ/√d_k，× K/√d_k
dQ                                           【同时反求 dK → 更新 Wk】
  ↓ Q = X·Wq
∂Loss/∂Wq = Xᵀ · dQ                        【Wq 的梯度】
  ↓
Wq = Wq - lr × ∂Loss/∂Wq                   【参数更新】
```

### 5.4 梯度的维度

| 对象 | 类型 | 说明 |
|---|---|---|
| Loss | 标量（1个数） | 如 2.35 |
| ∂Loss/∂Wq | 矩阵（与 Wq 同形） | 如 [768, 64] |
| 参数更新 | 逐元素相减 | Wq = Wq - lr × 梯度矩阵 |

### 5.5 所有参数同时更新

- 一次反向传播，**所有参数矩阵同时计算梯度，同时更新**
- 计算图是有向无环图（DAG），梯度从 Loss 节点拓扑顺序反向扫描
- 共享参数（如 Embedding）的梯度从所有使用处**累加**后再更新
- GPU 并行矩阵运算保证了几百亿参数的高效计算

### 5.6 显存压力

训练时显存需求 ≈ 参数量 × 4：
- 参数本身 × 1
- 梯度矩阵 × 1
- AdamW 维护的两份动量 × 2

## 六、推理过程

### 6.1 自回归生成

```
输入 Prompt → 前向传播 → 预测下一个 token → 追加到序列 → 继续...
直到输出 <EOS>
```

每次生成一个 token，**串行**，是推理慢的根本原因。

### 6.2 解码策略

| 策略 | 原理 | 特点 |
|---|---|---|
| Greedy | 每步取概率最高的词 | 快，易重复 |
| Beam Search | 保留 Top-K 候选路径 | 质量高，慢 |
| Temperature | 调整概率分布锐度 | 高温→随机，低温→确定 |
| Top-P (Nucleus) | 从累积概率 >P 的词中采样 | 平衡多样性和质量 |

### 6.3 KV Cache（推理加速核心）

```
无 KV Cache：每次重新算所有 token 的 K/V → O(n²)
有 KV Cache：缓存历史 K/V，只算新 token → O(n)
```

### 6.4 训练 vs 推理对比

| | 训练 | 推理 |
|---|---|---|
| 目标 | 最小化 Loss，更新参数 | 生成最优输出，参数固定 |
| 传播方向 | 前向 + 反向传播 | 只前向传播 |
| 并行性 | 序列内可并行（Causal Mask） | 每步串行生成 |
| 显存 | 参数 + 梯度 + 动量 | 参数 + KV Cache |
| 速度瓶颈 | GPU 算力、通信带宽 | 内存带宽（访存密集） |

## 七、核心公式速查

| 公式 | 含义 |
|---|---|
| `Q=X·Wq, K=X·Wk, V=X·Wv` | QKV 线性变换 |
| `Attention = softmax(QKᵀ/√d_k)·V` | 注意力计算 |
| `Loss = -log P(正确词)` | 交叉熵损失 |
| `∂Loss/∂Logits = softmax(Logits) - one_hot(y)` | CrossEntropy 梯度 |
| `∂Loss/∂Wq = Xᵀ · dQ` | Wq 的梯度 |
| `W = W - lr × ∂Loss/∂W` | 梯度下降更新 |
