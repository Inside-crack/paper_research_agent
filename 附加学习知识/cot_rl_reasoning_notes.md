# CoT 与 RL 推理训练学习笔记

> 主题：为什么 next-token prediction 容易“想都不想直接答”，以及 CoT、RL 推理训练、GRPO、DeepSeek / Kimi 等路线如何逐步解决这个问题。

## 1. 原始问题：next-token prediction 为什么容易“想都不想直接答”？

### 问题

大语言模型的基础训练目标通常是 **next-token prediction**：给定前文，预测下一个 token。

形式上可以写成：

$$
\max_\theta \sum_{t} \log p_\theta(x_t \mid x_{<t})
$$

也就是让模型尽可能提高真实下一个 token 的概率。

### 背景

这个目标本质上训练的是：

> 在当前上下文下，什么 token 最像人类语料里接下来会出现的 token？

它非常适合学习语言、知识、风格和常见模式，但它并不天然要求模型：

- 先分析问题；
- 拆解步骤；
- 验证中间结论；
- 回溯错误路径；
- 在多个候选答案中搜索最优解。

所以在很多问题上，模型会倾向于直接生成看起来最可能的答案。

### 为什么会“想都不想直接答”？

因为训练目标奖励的是“下一个 token 像不像”，而不是“推理过程好不好”。

例如用户问：

> 17 × 23 等于多少？

模型可以直接根据语料模式猜一个答案，也可以先算：

$$
17 \times 23 = 17 \times (20 + 3) = 340 + 51 = 391
$$

但基础 next-token prediction 并不会明确奖励“先写计算步骤再回答”。

### 直觉总结

next-token prediction 像是在训练模型“接话接得像”，而不是训练模型“认真思考后再答”。

---

## 2. 解法①：CoT 思维链（Chain-of-Thought, 2022）

### 问题

既然模型容易直接给答案，那能不能让它先把推理过程写出来？

这就是 CoT 的核心思路。

### 背景

CoT，即 Chain-of-Thought，思维链。它通过提示模型生成中间推理步骤，再给最终答案。

典型形式：

```text
Question: xxx
Let's think step by step.
Reasoning: ...
Answer: ...
```

### Few-shot CoT

Few-shot CoT 会在 prompt 里给几个带推理过程的示例。

```text
Q: 小明有 3 个苹果，又买了 4 个，现在有几个？
A: 小明原来有 3 个，后来又买了 4 个，所以一共有 3 + 4 = 7 个。答案是 7。

Q: 小红有 10 元，花了 6 元，还剩多少？
A: 小红原来有 10 元，花掉 6 元，所以还剩 10 - 6 = 4 元。答案是 4。
```

模型看到这种格式后，会模仿“先推理、再回答”。

### Zero-shot CoT

Zero-shot CoT 不提供示例，只加一句经典提示：

```text
Let's think step by step.
```

或者中文：

```text
让我们一步一步思考。
```

这能显著提升模型在数学题、逻辑题、多跳问答中的表现。

### 为什么写步骤能提高准确率？

#### 直觉一：外部草稿纸

人做复杂题时也很难在脑中一步到位，通常会写草稿。

CoT 相当于让模型把中间状态写到上下文里：

- 前一步推理会成为后一步的输入；
- 模型不必把全部中间变量都压在隐状态里；
- 长问题被拆成多个短问题。

所以 CoT 像给模型一张外部草稿纸。

#### 直觉二：复杂映射拆分

没有 CoT 时，模型要学习的是：

$$
\text{Question} \rightarrow \text{Answer}
$$

这可能是一个很复杂的映射。

有 CoT 后，映射变成：

$$
\text{Question} \rightarrow \text{Step}_1 \rightarrow \text{Step}_2 \rightarrow \cdots \rightarrow \text{Answer}
$$

复杂问题被拆成多个更简单的局部预测任务。

### CoT 的局限

#### 1. 可能产生伪推理

模型可能写出看起来合理、但实际并不支持答案的推理过程。

也就是说：

> CoT 不保证模型真的在推理，它也可能只是在生成“像推理的文本”。

#### 2. 依赖 prompt

CoT 往往需要 prompt 触发，例如：

- “Let's think step by step”；
- few-shot 推理样例；
- 特定格式约束。

如果 prompt 不好，效果可能下降。

#### 3. 不奖励推理质量

基础 CoT 主要是推理格式上的诱导，并没有直接训练模型：

- 哪种推理路径更好；
- 哪个中间步骤错了；
- 是否应该验证答案；
- 是否应该回溯。

### 直觉总结

CoT 是从“直接答”升级到“先写步骤再答”。它主要是 prompt 技巧，让模型显式展开中间过程，但还没有把“会推理”变成训练目标本身。

## 3. 解法②：RL 推理训练（o1 / R1 路线）

### 问题

CoT 能提升效果，但它仍然偏 prompt 技巧。那能不能直接训练模型，让它学会为了最终正确答案而推理？

这就是 RL 推理训练的核心。

### 背景

RL，即 Reinforcement Learning，强化学习。

在推理训练中，模型不只是模仿语料，而是生成解题过程和答案，然后根据结果获得奖励。

简化形式：

$$
\max_\theta \mathbb{E}_{y \sim \pi_\theta(\cdot \mid x)}[R(x, y)]
$$

其中：

- $x$ 是问题；
- $y$ 是模型生成的完整回答，包括推理和答案；
- $R(x, y)$ 是奖励函数；
- $\pi_\theta$ 是当前模型策略。

### Outcome Reward

很多推理任务可以用最终答案判断对错，例如数学、代码、逻辑题。

这类奖励叫 outcome reward：

$$
R(x, y) =
\begin{cases}
1, & \text{最终答案正确} \\
0, & \text{最终答案错误}
\end{cases}
$$

它不一定判断每一步是否正确，但会奖励能导向正确答案的整体生成。

### 从 prompt 技巧升级为训练目标

CoT 是告诉模型：

> 你最好一步一步想。

RL 推理训练是告诉模型：

> 你怎么想都可以，但最终答对才有奖励。能稳定答对的推理行为会被强化。

这会让模型逐渐学到：

- 多写关键步骤；
- 自我检查；
- 尝试不同路径；
- 发现矛盾后修正；
- 在复杂问题上投入更多计算。

### Test-time Compute Scaling

推理能力还有一个关键现象：测试时计算量可以扩展。

也就是模型在回答时可以花更多 token、更多步骤、更多采样或搜索，来提高正确率。

直觉上：

> 简单题少想，复杂题多想。

这就是 test-time compute scaling。

### 从线性推理到搜索 / 验证 / 回溯

早期 CoT 更像线性推理：

```text
Step 1 → Step 2 → Step 3 → Answer
```

RL 推理训练希望模型学到更复杂的行为：

```text
尝试路径 A → 发现问题 → 回溯
尝试路径 B → 验证通过 → 输出答案
```

它不只是“写步骤”，而是更接近“搜索解空间”。

### CoT vs RL 推理训练对比

| 维度 | CoT | RL 推理训练 |
|---|---|---|
| 核心方式 | Prompt 诱导 | 训练目标强化 |
| 主要目标 | 让模型写出步骤 | 让模型为了答对而学会推理 |
| 奖励机制 | 通常没有显式奖励 | 有 outcome reward 或 rule-based reward |
| 是否依赖 prompt | 较依赖 | 相对更内化 |
| 推理形态 | 多为线性步骤 | 可出现搜索、验证、回溯 |
| 局限 | 伪推理、格式依赖 | 奖励设计难、训练成本高、稳定性挑战 |

### 直觉总结

CoT 是“让模型把思考写出来”，RL 推理训练是“让模型因为答对而学会怎样思考”。

## 4. GRPO 算法（DeepSeek-R1）

### 问题

传统 PPO 强化学习能训练推理，但成本高、系统复杂。有没有更简单、更适合推理任务的算法？

DeepSeek-R1 使用的关键方法之一是 GRPO。

### PPO 的四大难点

PPO，即 Proximal Policy Optimization，是 RLHF 中常见算法。

在大模型推理训练中，它通常面临四类问题。

#### 1. Reward Model 成本高

传统 RLHF 往往需要训练 Reward Model，用来评价回答质量。

但推理任务里，很多题本身可以用规则判断答案对错，例如：

- 数学题答案是否一致；
- 代码是否通过测试；
- 格式是否符合要求。

这时再训练复杂 Reward Model 成本很高。

#### 2. Value Model 成本高

PPO 通常还需要 Value Model 估计状态价值。

这意味着训练中要维护额外模型，增加显存和工程复杂度。

#### 3. 稀疏奖励

很多推理任务只有最终答案对错，中间步骤没有奖励。

这会导致奖励信号稀疏：

```text
推理了 1000 个 token，最后只得到 0 或 1。
```

#### 4. 训练不稳定

大模型 RL 容易出现：

- 策略更新过猛；
- KL 发散；
- 奖励被模型投机利用；
- 输出长度异常增长；
- 推理格式坍缩。

### GRPO 如何简化 PPO？

GRPO，全称 Group Relative Policy Optimization。

它的核心思想是：

> 对同一个问题采样多个回答，比较这一组回答内部谁更好，用组内相对优势来更新模型。

### 省掉 Reward Model

在数学、代码等任务里，GRPO 可以使用 rule-based reward。

例如：

- 答案正确：1；
- 答案错误：0；
- 格式正确：额外加分；
- 代码通过测试：奖励更高。

这避免了训练单独的 Reward Model。

### 省掉 Value Model

GRPO 不再依赖 Value Model 估计 baseline，而是用同一问题下多次采样的组内平均奖励作为 baseline。

假设对同一个问题 $x$ 采样 $G$ 个回答：

$$
y_1, y_2, \dots, y_G
$$

对应奖励：

$$
r_1, r_2, \dots, r_G
$$

组内均值为：

$$
\bar{r} = \frac{1}{G}\sum_{i=1}^{G} r_i
$$

组内标准差为：

$$
\sigma = \sqrt{\frac{1}{G}\sum_{i=1}^{G}(r_i - \bar{r})^2}
$$

相对优势可以写成：

$$
A_i = \frac{r_i - \bar{r}}{\sigma}
$$

如果某个回答比同组其他回答更好，它的优势就是正的；反之为负。

### 数学直觉

GRPO 不问“这个回答绝对值是多少”，而是问：

> 对同一道题，模型自己生成的几个答案里，哪个更好？

这很适合推理训练，因为同一道题可以采样出多种解法：

- 有的直接猜错；
- 有的推理一半错；
- 有的完整推理并答对；
- 有的答对但格式不规范。

通过组内比较，模型能强化相对更好的行为。

### PPO vs GRPO 对比

| 维度 | PPO | GRPO |
|---|---|---|
| 是否需要 Reward Model | 通常需要 | 可用 rule-based reward，很多场景不需要 |
| 是否需要 Value Model | 通常需要 | 不需要，用组内相对奖励替代 |
| Baseline 来源 | Value Model | 同一问题多样本奖励均值 |
| 工程复杂度 | 高 | 相对低 |
| 适合任务 | 通用偏好对齐 | 数学、代码、可验证推理任务 |
| 主要风险 | 训练不稳定、成本高 | 依赖可验证奖励，组采样成本较高 |

### R1-Zero vs R1

| 维度 | R1-Zero | R1 |
|---|---|---|
| 起点 | 基座模型直接 RL | 先冷启动 / SFT，再 RL |
| 特点 | 能自发出现长推理、反思、验证 | 可读性更好，稳定性更强 |
| 问题 | 输出混乱、可读性差、语言混杂 | 工程上更实用 |
| 意义 | 证明纯 RL 可激发推理能力 | 形成更可用的推理模型 |

### GRPO 的适用边界

GRPO 特别适合：

- 数学题；
- 代码题；
- 有标准答案的问题；
- 可自动验证的任务；
- 格式可规则检查的任务。

不太适合：

- 开放式创作；
- 主观审美评价；
- 没有明确对错的复杂任务；
- 奖励函数容易被投机利用的任务。

### 直觉总结

GRPO 的关键是：

> 不训练一个裁判模型，也不训练价值模型，而是让模型对同一道题生成多个答案，再用组内相对好坏来学习。

## 5. DeepSeek-V4 在推理训练上的升级

### 问题

如果 R1 代表推理 RL 的一次突破，那么后续模型如何继续升级？

方向不再只是“单模型做 RL”，而是把推理能力建设成一条生产线。

### 背景

DeepSeek-V4 这一类后续推理模型的升级，可以从几个方向理解：

- 多领域专家强化；
- on-policy distillation；
- 长上下文能力绑定；
- Agent 能力绑定；
- 从单次训练升级为持续生产推理数据和能力。

### 多领域专家强化

早期推理 RL 多集中在数学、代码等可验证任务。

更强的推理模型需要覆盖：

- 数学；
- 代码；
- 科学问答；
- 工程诊断；
- 工具调用；
- 长文档分析；
- 多轮任务规划。

这意味着 RL 数据、奖励函数和训练策略都要按领域设计。

### On-policy Distillation

传统蒸馏常常是让学生模型模仿教师模型已有输出。

On-policy distillation 更强调：

> 学生模型在自己当前策略下生成样本，再由教师或验证器提供反馈，学生学习更适合自己分布的推理行为。

这能减少“老师答案很好，但学生模仿不了”的问题。

### 与长上下文能力绑定

推理不只发生在短题里。

现实任务经常需要：

- 阅读长文档；
- 跨章节查找证据；
- 维护长期任务状态；
- 在大量上下文中定位关键条件。

所以推理训练需要和长上下文结合。

### 与 Agent 能力绑定

Agent 场景中，模型不仅要回答，还要：

- 制定计划；
- 调用工具；
- 观察工具结果；
- 调整下一步；
- 处理失败；
- 完成长期目标。

这使推理从“文本内部推理”升级为“行动中的推理”。

### 直觉总结

DeepSeek-V4 式升级可以理解为：

> 从训练一个会解题的模型，升级为建设一条持续生产、迁移和强化推理能力的系统。

## 6. 开源模型 RL 推理训练的理论创新

### 问题

R1 之后，开源模型如何继续推进 RL 推理训练？

不同工作从上下文长度、优化粒度、探索稳定性、搜索内化、奖励设计等方面继续创新。

---

### 6.1 Kimi k1.5：128k RL 与 partial rollout

#### 背景

Kimi k1.5 强调长上下文推理，把 RL 扩展到更长上下文场景。

#### 关键点

- 支持长上下文，比如 128k；
- 在长文本任务中训练模型进行推理；
- 使用 partial rollout 降低完整长序列 rollout 的成本。

#### 直觉

长上下文 RL 的难点是：如果每次都完整生成超长轨迹，成本非常高。

partial rollout 类似于：

> 不一定每次都把整条长轨迹跑完，而是在关键片段上训练和评估。

---

### 6.2 GSPO：Sequence-level Optimization

#### 背景

很多 RL 方法在 token 级别计算概率和优势，但推理质量往往体现在整个序列上。

#### 关键点

GSPO 更强调 sequence-level optimization，即从完整回答序列层面优化。

#### 直觉

一个推理答案不是单个 token 好就行，而是整体路径要好。

所以优化目标从：

$$
\text{token-level good}
$$

转向：

$$
\text{sequence-level good}
$$

---

### 6.3 DAPO：防止 entropy collapse

#### 背景

RL 训练中，模型可能过早收敛到单一模式，探索能力下降。

这叫 entropy collapse，熵坍缩。

#### 关键点

DAPO 关注如何保持策略多样性，避免模型只会生成一种固定推理模板。

#### 直觉

如果模型太早变得“自信但狭窄”，它可能不再探索新解法。

推理训练需要一定多样性：

- 尝试不同路径；
- 保留创造性；
- 避免模板化长推理。

---

### 6.4 Satori / COAT：搜索内化

#### 背景

很多强推理系统依赖外部搜索，例如 tree search、best-of-N、verifier rerank。

Satori / COAT 这类方向关注：能否把搜索能力内化进模型。

#### 关键点

模型不只是生成一条 CoT，而是学习类似搜索的内部行为：

- 分支；
- 比较；
- 验证；
- 回溯；
- 选择。

#### 直觉

外部搜索像是在模型外面套一个解题器。

搜索内化则希望模型自己学会：

> 我现在这条路不对，应该换一种思路。

---

### 6.5 RLVR：奖励设计

#### 背景

RLVR，即 Reinforcement Learning with Verifiable Rewards。

核心是用可验证奖励训练模型。

#### 常见奖励

- 数学答案是否正确；
- 代码是否通过单元测试；
- 证明是否满足形式系统；
- 格式是否合规；
- 工具调用结果是否达成目标。

#### 直觉

RLVR 的优势是奖励客观、便宜、可扩展。

但它也有边界：

- 只适合可验证任务；
- 奖励函数设计不当会被投机；
- 只看最终答案可能忽略过程质量。

---

### 6.6 冷启动问题

#### 问题

如果模型一开始完全不会推理，直接 RL 可能很难学起来。

因为它采样出来的答案大多是错的，奖励几乎全是 0。

#### 解决方式

常见冷启动方法包括：

- 先用高质量 CoT 数据 SFT；
- 使用教师模型生成初始推理数据；
- 从简单任务开始 curriculum learning；
- 先训练格式和可读性，再进行 RL；
- 混合人工数据和自动验证数据。

#### 直觉

RL 需要探索，但如果起点太差，模型连“偶尔答对”都做不到，就很难收到有效奖励。

所以冷启动相当于先把模型带到“能开始练习”的水平。

## 7. Kimi K3：1M Context Agentic RL

### 问题

如果 k1.5 把 RL 推理扩展到 128k 长上下文，那么下一步是什么？

Kimi K3 的方向可以理解为：

> 更长上下文、更强 Agent 任务、更持久的 rollout、更细粒度的 effort 控制。

### 背景

相关论文：arXiv 2607.24653。

关键词包括：

- 1M context；
- agentic RL；
- persistent rollout；
- multi-effort RL；
- Multi-Teacher On-Policy Distillation。

### 1M Context Agentic RL

1M context 意味着模型可以在百万级 token 上下文中工作。

这会带来新的推理任务：

- 长项目代码理解；
- 大规模文档问答；
- 长期任务状态追踪；
- 多工具、多步骤 Agent 执行；
- 跨大量证据进行推断。

Agentic RL 则强调模型在环境中行动，而不是只在文本里回答。

### Persistent Rollout

普通 rollout 通常是一轮问题生成一轮答案。

Persistent rollout 更像长期任务轨迹：

```text
观察环境 → 制定计划 → 调用工具 → 得到反馈 → 修改计划 → 继续执行
```

它适合训练模型完成多步骤真实任务。

### Multi-effort RL

不同问题需要不同推理预算。

Multi-effort RL 训练模型适应多种 effort 档位：

- low effort：快速回答简单问题；
- medium effort：中等复杂度推理；
- high effort：复杂问题深入搜索和验证。

这对应真实使用中的成本控制。

### Multi-Teacher On-Policy Distillation

多个教师模型可以提供不同能力：

- 数学教师；
- 代码教师；
- 长上下文教师；
- Agent 教师；
- 验证器或裁判模型。

On-policy 的含义是学生在自己的生成分布上学习，而不是只模仿教师离线数据。

### Kimi K3 vs k1.5 对比

| 维度 | Kimi k1.5 | Kimi K3 |
|---|---|---|
| 上下文长度 | 128k 级别 | 1M 级别 |
| 重点 | 长上下文 RL 推理 | 长上下文 Agentic RL |
| Rollout | partial rollout 降低成本 | persistent rollout 面向长期任务 |
| 推理预算 | 更偏长 CoT / 长上下文 | multi-effort，不同任务不同预算 |
| 蒸馏 | 长上下文推理蒸馏 | Multi-Teacher On-Policy Distillation |
| 目标 | 提升长上下文推理 | 提升长期 Agent 执行与复杂任务能力 |

### 直觉总结

Kimi K3 把推理训练从“长题解答”进一步推向“长上下文、多步骤、可持续行动的 Agent 训练”。

---

## 8. 总体脉络总结

### 从 next-token prediction 到 CoT

基础模型学会的是：

> 根据上下文预测下一个 token。

CoT 让模型开始：

> 显式写出中间推理步骤。

### 从 CoT 到 RL 推理训练

CoT 主要靠 prompt 诱导。

RL 推理训练则把目标改成：

> 生成能获得高奖励的推理轨迹。

### 从 PPO 到 GRPO

PPO 成本高，需要 Reward Model 和 Value Model。

GRPO 用组内相对奖励简化训练，特别适合数学、代码等可验证任务。

### 从单题推理到 Agentic RL

后续模型继续扩展到：

- 长上下文；
- 多领域；
- 多教师蒸馏；
- 搜索内化；
- 长期工具调用；
- 多 effort 推理预算。

---

## 9. 一句话总览

| 阶段 | 核心变化 | 直觉 |
|---|---|---|
| Next-token prediction | 预测下一个 token | 接话接得像 |
| CoT | Prompt 诱导写步骤 | 给模型草稿纸 |
| RL 推理训练 | 用奖励强化推理行为 | 答对才有奖励 |
| GRPO | 组内相对奖励优化 | 同题多个答案比好坏 |
| R1 / o1 路线 | 推理能力内化 | 学会搜索、验证、回溯 |
| DeepSeek-V4 / Kimi K3 | 推理生产线与 Agentic RL | 从会解题到会长期行动 |

---

## 10. 最终直觉总结

这条技术线可以用一句话概括：

> 大模型最初只是学会“像人一样接着说”，CoT 让它“把思考写出来”，RL 推理训练让它“因为答对而学会更好的思考方式”，而 GRPO、长上下文 RL、Agentic RL 等方法，则进一步把这种能力扩展成可训练、可验证、可迁移的推理系统。
